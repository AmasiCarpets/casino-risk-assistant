Crash Fairness Lab 🤖

تعلّم كيف تعمل Server Seed وClient Seed وNonce وHMAC‑SHA256، وتحقق من الجولات بعد كشف البذرة.

مهم: هذا التطبيق لا يتنبأ بالجولة القادمة، ولا يعطي إشارات دخول أو خروج. وظيفته تعليمية والتحقق من البيانات بعد توفرها.

1) التحقق من التزام Server Seed

أدخل Server Seed بعد كشفه، ثم ألصق الـSHA‑256 Hash الذي كان ظاهرًا قبل الجولة. التطبيق يحسب الهاش ويتأكد هل يطابق الالتزام السابق.

الهاش المحسوب: —
أدخل البيانات ثم اضغط تحقق.

2) توليد HMAC‑SHA256

وفق آلية التوليد المعلنة، يكون Server Seed هو مفتاح HMAC، والرسالة بالشكل: ClientSeed:Nonce:Round.

3) شاهد أثر تغيير Nonce

استخدم نفس البذرتين، ثم ولّد عدة قيم متتابعة. ستلاحظ أن تغيير Nonce وحده ينتج HMAC مختلفًا بالكامل.

كيف يعمل النظام؟

Server Seed

قيمة سرية يولدها الخادم، ويُنشر Hash لها مسبقًا لمنع تغييرها لاحقًا.

Client Seed

قيمة يملكها المستخدم وتشارك في التوليد، لذلك لا يعتمد الناتج على الخادم وحده.

Nonce

رقم يزداد مع كل رهان. حتى مع ثبات البذرتين، تغييره ينتج ناتجًا جديدًا.

HMAC‑SHA256

دالة تشفير تنتج 32 بايت. تُحوّل بعض هذه البايتات لاحقًا إلى أحداث اللعبة.

لماذا لا يظهر الرقم القادم؟

قبل كشف Server Seed، لا تملك المفتاح الكامل اللازم لإعادة الحساب. بعد كشفه يمكنك التحقق من أن الهاش يطابق الالتزام السابق، ثم إعادة توليد النتائج الماضية.
